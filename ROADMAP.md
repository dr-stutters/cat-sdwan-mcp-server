# cat-sdwan-mcp-server roadmap
_Last updated 2026-10-23 (spec sweep: W16–W28 added from the Manager's own OpenAPI document; every tag is mapped in [docs/spec-coverage.md](docs/spec-coverage.md)). W0–W9 are done and released (v0.1.0, v0.2.0); W10 is built and its issue is open. Suite roadmap: [stutters-mcp-core/ROADMAP.md](https://github.com/dr-stutters/stutters-mcp-core/blob/main/ROADMAP.md). Owner decision record: core [C42](https://github.com/dr-stutters/stutters-mcp-core/issues/94) (the SD-WAN Manager half)._

## Summary
- **What it is.** An MCP server on `stutters-mcp-core` for Cisco Catalyst SD-WAN Manager (formerly vManage): fabric inventory and device health, control connections, OMP, BFD and tunnels, application-aware routing (app-route) SLA, alarms, events and the audit log, then preview-first configuration-group, template and onboarding writes and a dangerous tier for policy activation, reboots and upgrades. Repo `cat-sdwan-mcp-server`, package `cat_sdwan_mcp`, tool prefix `catsdwan` (not `sdwan`: Catalyst SD-WAN gets its own tooling, apart from FTD SD-WAN in fmc), settings prefix `CATSDWAN_`, host port 8041, item ids W0–W28.
- **Versions.** Planned against **20.18** (the last 20.x control-component release, Aug 2025, paired with IOS XE SD-WAN 17.18; the images already installed in CML are Manager, Controller and Validator 20.18.3.1 and edge 17.18.02) and **26.x** (SD-WAN moved to IOS XE year numbering: 26.1.1 Feb 2026, 26.2.1 Aug 2026, 27.1.1 due Feb 2027; every release from 26.1.1 on is an Extended Support release with 48 months of support). 20.15 is best effort (maintenance to 2027-03-30). 20.12 and older are out (no maintenance releases after 2026-03-30).
- **API choice.** One REST surface, `/dataservice` on the Manager, with its own OpenAPI document (Swagger UI at `/apidocs`, raw document `GET /apidocs/vmanageapi.json` after a login: OpenAPI 3.0.1, on 20.18.3.1 2,811 paths, about 4,100 operations in 379 tags). **Spec sweep (2026-10-23):** every tag is mapped to an item, to `catsdwan_api_call` or to Not planned in [docs/spec-coverage.md](docs/spec-coverage.md) (`scripts/spec_coverage.py`, rerun per release in W15). Paths this roadmap marked unverified that the 20.18.3.1 spec confirms: `/clusterManagement/health/status` (W1), `/device/action/reboot` and `/device/action/changepartition` (W12), `/template/policy/vsmart/activate/{policyId}` and `/deactivate/{policyId}` (W11; also `/activate/central/{policyId}`), `/statistics/approute/aggregation` (W4), `/v1/config-group/{id}/device/{deviceId}/preview` (W8: in use) and `/v1/policy-group/{id}/device/{deviceId}/preview` (W21). Login: JWT (`POST /jwt/login`, from 20.18.1: `token`, `refresh`, `csrf` in one response, `POST /jwt/refresh`, no logout) by default, falling back to the session login (`POST /j_security_check` form, `JSESSIONID` cookie, `GET /dataservice/client/token` for the `X-XSRF-TOKEN` header, `POST /logout` on close) for 20.15 and when JWT is refused. Real-time device reads (`/dataservice/device/<feature>?deviceId=<system-ip>`) ask the device through the Manager; statistics reads (`/dataservice/statistics/<type>`, a JSON query body) read the Manager's own database. Rate limits since 20.6: 100 requests/s, bulk APIs 48/min, at most 2 concurrent bulk statistics requests, 100 concurrent sessions per user (one Cisco page says 250: unverified), so the client pools one login and throttles.
- **Why it fits the suite.** A customer running Catalyst SD-WAN next to FMC, Catalyst Center and ISE today cannot read BFD and tunnel state, app-route SLA, alarms or device health through the suite, nor push a configuration group or onboard an edge. Unlike Meraki or Umbrella it can be proven in this lab: the CML controller has every SD-WAN image, and `cml_apply_link_scenario` can degrade a WAN link to prove that app-route and BFD tools see it. Legacy device templates have a documented intended-config preview (`POST /dataservice/template/device/config/config`), which is the preview-first contract; a public API for the configuration-group CLI preview the GUI shows is unverified (W8).
- **The line with fmc-mcp-server.** `fmc_sdwan_*` (fmc F51–F54) is FTD's own SD-WAN (FMC SD-WAN topologies of FTD hubs and branches). It shares only the name with this server; the two never manage the same device. To keep the two apart for an assistant connected to both, this server's prefix is `catsdwan` and fmc's FTD SD-WAN tools get `ftdsdwan` names later ([fmc F86](https://github.com/dr-stutters/fmc-mcp-server/issues/323)). A branch that runs a Catalyst SD-WAN edge in front of an FTD is the only shared story, and it lives in a prompt (W10), not in shared tools.
- **Other MCP servers.** CiscoDevNet's `catalyst-sdwan-mcp-community` (MIT, TypeScript, about 40 read-only `get_`/`list_` tools without a prefix, JWT on 20.18.1+, 9 commits, no releases) and a third-party `cisco-sdwan-mcp` on PyPI exist. The Manager ships an "AI Assistant (BETA)" chat, not an MCP server (unverified for 26.2). This server earns its place with the suite's preview-then-confirm writes, roles, rails, audit and multi-instance, and with prompts that chain CML, NetBox, ISE and FMC.
- **Now delivers:** the lab fabric (W0), the client and preflight (W1) and the read tools operators ask for first (W2–W5). **Next:** spec discovery (W6), configuration reads (W7), the preview-first writes (W8–W9), three prompts (W10), then from the spec sweep certificates (W16), on-box troubleshooting (W17) and device state reads (W18). **Later:** policy (W11), device operations (W12), SLA history (W13), and from the sweep path insight (W19), configuration history (W20), feature-profile writes (W21), site and tunnel health (W22), edge security reads (W23), TrustSec and integrations (W24), Manager operations (W25), access and AAA (W26), controller upgrades (W27) and licensing (W28). **Production gate:** W14–W15.

## Not planned
Left to `catsdwan_api_call` (with `catsdwan_search_spec` / `catsdwan_get_definition` from W6) or out of scope:
- **vEdge (Viptela OS) edges.** The image is in CML, but vEdge is end-of-life; reads work through the same APIs, and nothing is proven or written for it.
- **Event ingestion of any kind**: alarm webhooks, streaming telemetry, data-stream export, SNMP traps (ADR-003).
- **Manager administration changes**: cluster setup and removal, disaster recovery registration and failover, restores, Manager upgrades, certificate authority settings, licence assignment, user and tenant creation (beyond W14's user-group script). Health, backups, users, AAA and licences are read in W25, W26 and W28; controller upgrades are W27.
- **Security policy on the edges** (UTD/Snort, URL filtering, zone-based firewall, SSL proxy, IPS signature sets): read through `catsdwan_get_policy` (W11) and `catsdwan_security_status` / `catsdwan_security_events` (W23), never written here; firewalling in this suite belongs to FMC.
- **Areas of the spec the lab cannot prove** (from the 2026-10-23 sweep; 111 tags, about 900 operations): Cloud OnRamp, multicloud and Multicloud Interconnect, CloudExpress, Azure, SIG configuration and Cisco cloud services (cloud accounts); NFVirtual and Mobility feature profiles, colocation, app hosting and containers (hardware); cellular, voice, wireless, DSL, SFP, AppQoE and TCP optimisation (modules the CML edge lacks; their real-time reads remain reachable through `catsdwan_device_state` where a device has the feature); provider-mode multitenancy; SD-AVC, protocol packs and WAN Insights recommendations; FedRAMP, HSEC, TAC cases, ACI and WCM partner plumbing. Each is a candidate item if a customer asks.
- **Left to `catsdwan_api_call`** (118 tags, about 940 operations): the legacy policy list and definition builders (read through W11), Manager settings, network design, alarm notification rules, the Manager's own scheduled reports, packet capture, speed test and log streaming (they need a browser session), and Manager utility endpoints.
- **Direct device access.** Edge CLI goes through `cml_run_commands` in the lab; an edge in SD-WAN mode is managed only through the Manager, so this server never SSHes to edges.
- **Proxying the CiscoDevNet community MCP server** or the Manager's AI Assistant.
